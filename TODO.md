# Raabta AI — outcome tracker

## Delivered in the current app source

- [x] **Raabta brand and one-hand mobile UI.** The app is named Raabta AI (رابطہ), uses its original paired-arc brand mark across native launcher/splash artwork, and follows a light ivory/teal visual system with a vertical conversation, compact action rail and fixed composer/navigation.
- [x] **Urdu/English and RTL presentation.** New installs open in Urdu with right-to-left layout; Settings offers a saved Urdu/English switch. Chat, navigation, research, core settings, roadmap and persisted task milestones follow the selected language, and editable/chat text uses automatic script direction.
- [x] **Open-source mobile foundation.** The implementation reuses the managed Expo Router / React Native starter plus Expo's established media, local-storage and secure-storage modules instead of creating a new native runtime. The project includes an MIT license and public-facing feature/limit documentation; no provider key is bundled.
- [x] **User-configured provider connection.** Settings accept a complete HTTPS OpenAI-compatible chat-completions URL, model ID and user-supplied API key; optional voice transcription accepts its own HTTPS endpoint and model. No real provider or key is preselected or hardcoded.
- [x] **Actual chat and transparent task history.** A sent question is submitted to the selected provider; no success answer is invented when configuration, network or provider requests fail. Stop/cancellation and safe actionable error paths are shown. The conversation displays separate truthful preparation, retrieval, dispatch, response, stop, failure and transcription events; local activity entries are excluded from the provider's conversation payload.
- [x] **Device-local conversations.** Users can start, list, reopen and resume conversations, with titles, messages, selected attachment metadata and task history saved in local app storage. No sign-up, login or cloud chat sync is required.
- [x] **Selected public-web research.** A user-triggered DuckDuckGo HTML search returns up to six real source links. A user-entered public HTTPS HTML/text/JSON/XML page can be fetched, bounded, saved as a readable local text excerpt and submitted with a question to the selected model. The UI/README disclose unsupported login-required sites and PDF/binary parsing and show sources; failed retrieval produces no invented citations.
- [x] **Selected image/document questions.** The user can choose images and readable text/Markdown/CSV/JSON/XML/HTML files for an explicit chat request. Inputs are bounded and copied to app-private storage as needed; images use a compatible provider's OpenAI-style vision payload. Only user-selected attachment contents are sent when the task runs.
- [x] **Optional voice transcription.** Voice-file selection and recording are explicit user actions; microphone permission is requested only for recording. A separate optional HTTPS transcription endpoint/model uses the separately stored key, enforces a 20 MB cap, and puts the transcript in the composer for user review rather than sending it automatically.
- [x] **Limited assistant workflows and visible actions.** Guided web research/source retrieval, attachment preparation and chosen-model answering are available as bounded, user-triggered flows. Each real retrieval/preparation/dispatch/result/stop/failure is visible in the chat. This is not a general autonomous agent or a screen-lock/background worker.
- [x] **Privacy and permission boundary.** Android API keys use SecureStore and are never included in chat history; Web Preview keeps them in session memory only. Chat/action history and non-secret preferences use device-local app storage, which is not separately encrypted by Raabta. The app discloses provider and DuckDuckGo transmissions, requests only feature-required runtime media permission, and does not claim account access.
- [x] **Honest staged roadmap and handoff docs.** Active chat/research/limited-assistant scope is distinguished from future user-authorized GitHub/YouTube, MCP/tool and account-agent connections. README documents model/provider setup, file limits, privacy, boundaries and the managed Android build path.

The GitHub repository has a fresh public-source history; Manus initialization metadata and dotenv files were excluded. The managed Mobile project's canonical repository remains Manus-managed, and this source export does not add any in-app GitHub account connection.
- [ ] **Native Android APK/AAB.** The source is not itself an installable APK. Save an accepted source checkpoint and use the managed project's Dashboard Android build; deliver an APK only after its actual build succeeds. No Android artifact is claimed yet.
- [ ] **Native device verification.** Verify SecureStore, local persistence, gallery/document pickers and the recording permission flow on an actual Android build/device; Expo Web Preview and TypeScript checks alone do not prove native behavior.
- [ ] **Live provider verification.** No provider URL/model/key was supplied. Confirm a real answer only after the user configures a compatible provider; vision and transcription also depend on the selected provider/model.

## Requested future work — not implemented

- [ ] **Permissioned agent integrations.** Add user-owned GitHub/YouTube or other account connections, tools/MCP and consequential actions in later explicit steps, with least-privilege scopes and per-action user approval. No account is connected in this app release.
